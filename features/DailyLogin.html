Mô tả

  • DailyLogin không phải lịch thưởng đăng nhập kiểu 7 ngày: nó là bộ ghi nhận "ngày server" nào người chơi đã vào game, lưu thành một cửa sổ trượt 180 ngày (bitset) trong byte array DailyLogin.
  • Dữ liệu này là nguồn cho nhiệm vụ "Log In for {0} Days!" (DailyLoginMissionTask) của Weekly Mission và các mission event, và đồng thời là lớp chống chỉnh giờ: nếu ngày đã ghi lớn hơn giờ server hiện tại quá 15 phút thì client coi là gian lận thời gian, ép refresh tiến trình từ server và hiện TimeHackDialog.
  • Ngày server đổi lúc 08:00 UTC.

Thiết kế chi tiết

Daily Login — sổ ghi 180 ngày đăng nhập cho nhiệm vụ “Log In for N Days” và lớp chống chỉnh giờ

Tóm tắt thiết kế

Code Không phải lịch thưởng đăng nhập. DailyLogin chỉ ghi lại ngày server nào người chơi đã vào game, dạng cửa sổ trượt 180 ngày (bitset trong byte array DailyLogin, key 29). Ngày server đổi lúc 08:00 UTC (trừ thêm 100 ms đệm).

Code Dữ liệu này nuôi nhiệm vụ “Log In for {0} Days!” (DailyLoginMissionTask) của Weekly Mission và mission event: tiến độ = số bit bật trong khoảng ngày của event (GetLoginDayCountBetween). Phần thưởng do config mission phía server quyết định.

Code Lớp chống chỉnh giờ: chỉ ghi khi “tin cậy” (chưa phát hiện gian lận, client không tự lùi giờ khi offline, đã từng có giờ server 'ST'). Nếu ngày đã ghi đi trước giờ server hơn 15 phút, client đánh dấu gian lận, ép server trả lại tiến trình chuẩn, xoá các ngày “tương lai” và hiện TimeHackDialog ở lần vào Home sau. Backend tắt được kiểm tra này qua GameSettings.

Live 11/11 Snapshot 11/11: byte array = '31§81§1' → đầu cửa sổ = ngày 20767, đã ghi 1 ngày đăng nhập (10/11/2026 theo ngày server).

Luồng người chơi từng bước

  1. Ghi nhận ngày đăng nhậpClientCode
    TryRecordLogin chạy khi ping server xong và ở mọi đầu luồng Home (sau launch, force home, thắng, thua). Ngày server = (giờ server − 100 ms − 8 giờ) / 1 ngày. Bit của ngày đó chưa bật thì bật, lưu, log 'DailyLogin - New server day recorded: {0}'.
  2. Không ghi khi không tin cậyClientCode
    IsTrusted = !IsTimeManipulationDetected && !IsOfflineClientTimeTakenBack && AppKeyValue('ST') > 0. Không thoả thì bỏ qua.
  3. Trượt cửa sổ 180 ngàyClientCode
    Ngày đầu tiên đặt làm đầu cửa sổ. Ngày cũ hơn đầu cửa sổ bị bỏ. Ngày vượt đầu cửa sổ + 179 thì ShiftWindow dồn bit cũ ra ngoài để ngày mới nằm ở ô cuối.
  4. Nhiệm vụ đăng nhập N ngàyGiao diệnCode
    DailyLoginMissionTask.GetTaskProgressAmount → GetLoginDayCountBetween(from, to); Weekly Mission đổi thời gian event sang ngày server và nghe OnNewServerDay để cập nhật thanh tiến độ khi sang ngày.
  5. Phát hiện chỉnh giờClientCode
    Mỗi lần ServerTimeHelper.UpdateTime có giờ server: nếu 08:00 UTC của LastSeenServerDay > giờ server + 15 phút → TimeManipulationDetected: ghi level lúc phát hiện (hoặc vòng Arena), lưu RefreshId, ResetRefreshIdAndSendPing ('Time manipulation detected!!! Force refresh progress!!!').
  6. Sửa tiến trìnhClientCode
    TryFixTimeManipulatedProgress: bỏ cờ phát hiện, bật cờ chờ dialog, ClampToServerDay xoá các bit sau ngày server thật (ngày server < đầu cửa sổ thì xoá sạch). Vẫn lệch thì log exception lên Firebase.
  7. TimeHackDialogGiao diệnCode
    Đầu luồng Home tiếp theo (launch, force home, thua): TryPushTimeManipulationDetectedDialog đẩy ShowTimeHackDialogAction(level, DailyLoginTimeHack = 2) báo giờ thiết bị không đúng.
  8. Backend tắt kiểm traServerCode
    GameSettings trong refresh → TimeHackControlDisabledByBackend: khôi phục RefreshId cũ, bỏ cờ phát hiện ('Time manipulation check is disabled by backend').

Vận dụng cho game khác

  • Tách “ghi nhận đăng nhập” thành một dịch vụ riêng (bitset nhiều ngày) để mọi nhiệm vụ/event dùng lại, thay vì mỗi event tự đếm.
  • Dùng chính sổ ngày đã ghi để phát hiện chỉnh giờ: ngày ghi vượt giờ server → ép tải lại tiến trình từ server, rồi báo người chơi.
  • Nhận định Rủi ro: hai mốc đổi ngày khác nhau (08:00 UTC và 05:00 địa phương) dễ gây khó hiểu khi một event “đăng nhập N ngày” chạy song song với quà hằng ngày. Nên thống nhất mốc hoặc hiển thị giờ reset.

Mở khóa & điểm vào

Luôn chạy (không có level gate). Chỉ ghi khi 'trusted': chưa phát hiện chỉnh giờ, ServerTimeHelper.IsOfflineClientTimeTakenBack = false và đã từng nhận giờ server (AppKeyValue 'ST' > 0). Backend có thể tắt kiểm tra chỉnh giờ qua GameSettings (TimeHackControlDisabledByBackend).

Điểm vào:

  • Không có UI riêng
  • Nhiệm vụ 'Log In for {0} Day(s)!' trong Weekly Mission / mission event (MissionTaskDailyLoginMissionSingle/Plural)
  • TimeHackDialog (origin DailyLoginTimeHack = 2) khi phát hiện chỉnh giờ

Cách hoạt động

  1. ToServerDayIndex(t) = (t − 8 giờ) / 1 ngày (DailyBoundaryOffsetInMs = 8 h, DayInMs = 86.400.000); get_CurrentServerDayIndex dùng giờ server trừ thêm 100 ms đệm (DayTransitionSafetyBufferInMs).
  2. TryRecordLogin được gọi khi ping server thành công và ở mọi đầu luồng Home (sau launch, sau khi bị đẩy về Home, sau thắng / thua level).
  3. Nếu trusted, DailyLoginProgress.TryRecordLogin(serverDay): lần đầu đặt WindowStartServerDay = serverDay; ngày nhỏ hơn đầu cửa sổ bị bỏ; nếu vượt quá đầu cửa sổ + 179 thì dịch cửa sổ (ShiftWindow) để ngày mới nằm ở ô cuối; bật bit (16 + offset) nếu chưa bật, lưu và log 'New server day recorded'.
  4. Mission đọc số ngày đăng nhập trong khoảng bằng GetLoginDayCountBetween(from, to) (đếm bit, kẹp vào cửa sổ 180 ngày).
  5. Mỗi lần ServerTimeHelper.UpdateTime nhận giờ server, IsThereTimeManipulation so LastSeenServerDay: nếu đầu ngày đó (08:00 UTC) > giờ server + 15 phút thì TimeManipulationDetected: đánh dấu, ghi lại level (hoặc vòng Arena) lúc phát hiện, lưu RefreshId rồi ResetRefreshIdAndSendPing để server trả tiến trình chuẩn.
  6. TryFixTimeManipulatedProgress kẹp tiến trình về ngày server thật (ClampToServerDay xoá các bit tương lai) và bật cờ chờ dialog; đầu luồng Home tiếp theo TryPushTimeManipulationDetectedDialog đẩy ShowTimeHackDialogAction(level, DailyLoginTimeHack).

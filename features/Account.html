Mô tả

  • Người chơi luôn bắt đầu bằng tài khoản khách (guest) do server cấp qua RegisterRequest; id/token được giữ trong DB App và sao lưu lên cloud của thiết bị (UserIdAndToken) để cài lại vẫn khôi phục được.
  • Từ Settings, Edit Profile, Choose Photo, Leaderboard và các event đôi (Pearls of Atlantis, Hidden Path, Weekly Contest) người chơi có thể đăng nhập Facebook / Google / Apple để lưu tiến trình và chơi với bạn bè.
  • Server trả một trong 8 trạng thái liên kết; nếu tài khoản mạng xã hội đã gắn với user khác, client chuyển hẳn sang user đó (đổi DB U_<id>, tải lại Home) và nhớ guest cũ để có thể quay về khi đăng xuất.
  • Tên người chơi tạo ở EnterNameDialog (tối thiểu 3 ký tự) và chỉ được đổi một lần.
  • Đây là lớp nền cho Team, Friends, Profile và mọi tính năng cần định danh.

Thiết kế chi tiết

Tài khoản — guest tự tạo, sao lưu cloud, liên kết Facebook/Google/Apple và đổi tên một lần

Cập nhật 12/11/2026 · đọc code build 34771 + config mặc định trong APK + snapshot thiết bị 11/11/2026. Nhãn:Codeđọc từ pseudo-c / dump.cs của build 34771Nhận địnhsuy luận thiết kế, không phải số liệu đọc được

Tóm tắt thiết kế

Code Người chơi luôn bắt đầu bằng tài khoản guest do server cấp (RegisterRequest, thử tối đa 10 lần, mỗi lần cách 5 giây). Id/token nằm trong DB App và được sao lưu lên cloud của thiết bị (khoá UserIdAndToken), để cài lại máy vẫn lấy lại được tài khoản (cách server dùng bản sao lưu là suy luận: client đọc nó ngay trước khi gửi đăng ký). Không có màn đăng nhập trước khi chơi.

Code Liên kết Facebook / Google / Apple từ Settings (Save Progress), Edit Profile, Choose Photo, Leaderboard bạn bè và các event đôi (Pearls of Atlantis, Weekly Contest, Hidden Path). Server trả 1 trong 8 trạng thái: guest được gắn vào platform thì giữ nguyên tiến trình; platform đã thuộc user khác thì client chuyển hẳn sang user đó (đổi DB, tải lại Home) và nhớ guest cũ để quay về khi đăng xuất.

Code Tên người chơi đặt ở EnterNameDialog (tối thiểu 3 ký tự, chặn ký tự lạ) và chỉ được đổi 1 lần (“You have one chance to change your username!”, nhập lại 2 lần rồi xác nhận). Xoá tài khoản đi qua Helpshift; server xoá rồi bật cờ, client tự xoá DB và thoát.

Luồng người chơi từng bước

  1. Tạo guest khi cài mớiClientCode
    User còn là temp (id 0): TryRegisterUser → RegisterLoop. Trước khi gửi, đọc bản sao lưu cloud tối đa 3 lần (cách 0,1 s). RegisterResponse trả UserId/UserToken; MigrateTempUser ghi vào App.LocalKeyValue ('Temp user is migrated as: {0}').
  2. Bấm đăng nhập mạng xã hộiNgười chơiCode
    ConnectWithFacebook / Google / Apple(origin): khoá xoay và chạm, khởi tạo SDK, đăng nhập SDK, rồi gửi ngay SocialConnectHttpCommand (platform 1 Facebook, 2 Apple, 3 Google; kèm tên, authCode, access/id token).
  3. Gắn vào guest hiện tạiServerCode
    Trạng thái 1/3/5/7 (GuestLinkedTo…, HaveAlreadyBeenConnected): giữ user, lưu FacebookId/GoogleId/AppleId, bạn bè cập nhật, dialog “Signed in with Facebook!”, analytics SocialConnect.
  4. Chuyển sang tài khoản đã liên kếtServerCode
    Trạng thái 2 (ConnectedToExistentAccount) hoặc 4/6/8 (NewUserWith…): lấy RefreshResponse đi kèm, lưu GuestId/GuestToken/GuestUserTag, gửi DetachUserFromDeviceRequest cho user cũ, đổi DB sang U_<id mới> và tải lại Home. Không có RefreshResponse thì coi như thất bại.
  5. Đăng nhập thất bạiGiao diệnCode
    Ẩn loading, mở lại xoay, SocialConnectResultDialog với chữ 'FacebookSignInFailText' (Google/Apple tương tự) và nút Try Again.
  6. Đăng xuấtNgười chơiCode
    Xác nhận ở SocialAreYouSureDialog (“Do you want to sign out?”). Có guest cũ và không còn platform nào khác thì quay về guest (ChangeUserToLocalOldUser, tải lại Home); không thì chỉ gỡ platform. Dialog “Signed out from Facebook!”.
  7. Đặt tên / đổi tênNgười chơiCode
    EnterNameDialog: dưới 3 ký tự → “Type at least three characters”; lần đầu không có nút đóng. Gửi UpdateUserNameRequest, analytics NameCreate. Đổi tên: nhập 2 lần (không khớp → 'ChangeNameNoMatchTemporaryText'), ChangeNameConfirmDialog “Your username will be:”, analytics NameChange; đã đổi rồi thì 'NoChangeNameTemporaryText'.
  8. Xoá tài khoản / đăng nhập nơi khácServerCode
    ResponsePackage có cờ 'deleted user' → reset consent, xoá cloud backup và các file DB (App, U_*), thoát app. RemoteDataWipeHelper xoá RemoteLevels, Saves, AssetBundles khi server yêu cầu. TCP UserConnectedFromOtherDeviceResponse ngắt kênh realtime trên máy cũ.

Vận dụng cho game khác

  • Guest tự động + sao lưu cloud: người chơi vào game ngay, không mất tiến trình khi cài lại, đăng nhập mạng xã hội chỉ là tuỳ chọn.
  • Gợi ý đăng nhập ở đúng chỗ cần định danh (bạn bè, leaderboard, event đôi, ảnh đại diện) thay vì ép ở đầu game.
  • Nhớ guest cũ khi chuyển sang tài khoản đã liên kết, để đăng xuất là quay lại được, tránh mất tài khoản do bấm nhầm.
  • Nhận định Rủi ro: liên kết vào platform đã có tài khoản sẽ thay toàn bộ tiến trình đang chơi bằng tài khoản kia mà không hỏi lại; nên có dialog so sánh hai tiến trình trước khi chuyển.

Mở khóa & điểm vào

Có từ lần mở app đầu tiên: UserManager.TryRegisterUser chạy khi user còn là temp (TempUserId = 0). Nút đăng nhập mạng xã hội luôn có trong Settings (SocialConnectOrigin.Settings = 1); không có điều kiện level trong code.

Điểm vào:

  • Lần mở app đầu tiên (đăng ký guest tự động)
  • Settings → Sign in with Facebook / Google / Apple (SocialConnectOrigin.Settings)
  • Edit Profile / Choose Photo (EditProfile = 2, ChoosePhoto = 3)
  • Leaderboard tab bạn bè (Leaderboard = 4)
  • Event đôi: Pearls of Atlantis (5), Weekly Contest (6), Hidden Path (7)
  • EnterNameDialog khi cần đặt tên (Profile, Prelevel, User Profile)
  • Dialog kết quả SocialConnectResultDialog

Cách hoạt động

  1. Khi cài mới, user là temp (id 0).
  2. UserManager.TryRegisterUser khởi động RegisterLoop (gọi RegisterUser rồi chờ 5 giây, lặp lại), tối đa MaxRegisterTryCount = 10 lần.
  3. Trước khi gửi, GetCloudBackupAndSendRegister đọc bản sao lưu cloud (BackupManager.GetUserValues, khóa UserIdAndToken) tối đa 3 lần, mỗi lần chờ 0,1 giây, rồi SendRegisterCommand gửi RegisterHttpCommand.
  4. UserRegisterResponseReceived lấy RegisterResponse.UserId/UserToken và MigrateTempUser chuyển user tạm sang id thật (ghi UserId, Token vào bảng LocalKeyValue của DB App, đặt user id cho MaxSdk).
  5. Kết nối mạng xã hội: ConnectWith{Facebook|Google|Apple}(origin) khóa xoay màn hình, khóa chạm, khởi tạo SDK (OnPlatformInitCompleted), đăng nhập SDK (OnPlatformConnectCompleted), rồi SendUserConnectRequest gửi SocialConnectHttpCommand(platform, userId, name, authCode, accessOrIdToken).
  6. UserConnectResponseReceived đọc SocialConnectResponse.SocialConnectStatus: 1/3/5/7 (guest được gắn vào platform hoặc đã gắn sẵn) giữ nguyên user; 2 (gắn vào tài khoản đã có) và 4/6/8 (user mới với platform) lấy RefreshResponse đi kèm rồi UserManager.ChangeUserWithProgress để đổi sang user mới, cập nhật giờ cài đặt server và điều khoản.
  7. Trước khi đổi, ChangeCurrentUser lưu GuestId/GuestToken/GuestUserTag và gửi DetachUserFromDeviceHttpCommand cho user cũ.
  8. Đăng xuất: nếu có guest cũ và không còn platform nào khác thì quay về guest (ChangeUserToLocalOldUser → ReturnToGuestFinished → tải lại Home), ngược lại chỉ gỡ platform.
  9. Mọi kết quả hiển thị qua SocialConnectResultDialog và gửi event SocialConnect.

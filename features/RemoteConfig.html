Mô tả

  • Royal Kingdom điều khiển gần như mọi thứ từ server qua 4 lớp: (1) AB test — server gửi AbData (id → nhóm A…H) kèm mọi response chính, client lưu ở bảng AbTestTableItem và mỗi tính năng đọc nhóm của cặp id user mới / user cũ; (2) GameSettings.Flags — 48 bit kill switch tắt từng sự kiện/tính năng; (3) config JSON có version cho từng sự kiện, FeatureDependency, TeamStar…, client gửi version đang có và chỉ nhận bản mới, thiếu thì dùng JSON mặc định trong Resources; (4) nội dung động (frame, badge, name style, emote, avatar) tải từ CDN theo ETag.
  • Tiến trình người chơi đồng bộ qua IntRemoteKeyValue (KeyName) và ByteArrayRemoteKeyValue (ByteArrayKeyName).

Tóm tắt thiết kế

Code Gần như mọi thứ trong game đổi được từ server mà không cần ra bản mới, qua 4 lớp: AB test (id → nhóm A…H, đi kèm mọi response chính), GameSettings.Flags (bit kill switch cho từng event / tính năng), config JSON có version cho từng event (client gửi version đang có, chỉ nhận khi có bản mới, thiếu thì dùng JSON mặc định) và nội dung động (khung, huy hiệu, kiểu tên, emote, avatar) tải từ CDN theo ETag.

CodeLive 11/11 Mỗi tính năng khai báo một cặp AB (user mới / user cũ) và lấy nhóm = Max của hai id. Live 11/11: bảng AB có 67 dòng; client bỏ qua im lặng 39 id đã kết thúc (EndedAbIds). Phần lớn AB chỉ đổi config server gửi xuống; chỉ vài AB có rẽ nhánh trong code (ví dụ SEB 28: nhóm B mở ở level 101, nhóm khác ở 301).

Code Kill switch tắt event ngay lập tức và huỷ luôn mission task của event đó. Một số bit là cờ hạ tầng: chống hack giờ (0), tắt preload scene (9), log DB cho hỗ trợ (10), tắt vignette (22), không xoá DB hỏng (24), Daily Login chống chỉnh giờ (47).

Live 11/11 Snapshot 11/11 có các config đi theo version: BlitzConfig v329, FeatureDependencyConfig v206, TeamStarAssetConfig v18. Danh mục cosmetic từ CDN gồm 28 khung, 20 huy hiệu (+20 bản 3D), 16 kiểu tên, 8 emote, 1 avatar.

Luồng người chơi từng bước

  1. Khởi động: nạp AB từ máyClientCode
    AbTestData.FillFromLocal đọc AbTestTableItem, nên mọi manager có nhóm AB ngay cả khi chưa có mạng. Nhóm cũ dùng tới khi server gửi bản mới.
  2. Response mang AbDataServerCode
    Register / Refresh / Ping / UpdateUserProgress / EnterAbTest đều mang AbData {AllTests, ActiveAbList}. UpdateProgress so với bản hiện tại; chỉ id đổi nhóm mới phát OnAbTestDataUpdated và gửi analytics “vào AB” (trừ id 90 và các id đã kết thúc).
  3. Tính năng đọc nhómClientCode
    AbTest.CreateAbTest(oldId, newId); GetAbTestGroup = Max(nhóm id mới, nhóm id cũ). Event dùng NewUserAbId / OldUserAbId của manager. Cơ chế AB do client tự gán theo device id (AClientAbTestManager) có sẵn; đường khởi tạo trong build 34771 chưa được xác minh, không suy ra không dùng chỉ từ danh sách lớp.
  4. GameSettings: kill switchServerCode
    UserManager.ProcessGameSettings: MaxLevel → LevelResolver, RichardsJourneyFlags → RichardsJourneyDisabledLevels, các bit hạ tầng. UserEventHandler chuyển Flags tới từng event manager (DisabledByBackend theo get_DisabledBit); emote bit 42, Welcome Back bit 36, Wild Card bit 38.
  5. Config event có versionServerCodeAPK
    Get*EventInfo gửi ConfigVersion đang có; server trả {ConfigVersion, Config} khi có bản mới. AEventDataHelper.UpdateConfig lưu bản User / Server vào *TableItem; rỗng thì “LoadDefaultConfig” từ Resources (29 file JSON mặc định).
  6. ClientSettingsServerCodeLive 11/11
    Bật / tắt đo mạng (game, social, message, purchase), App Check, RegionChatBanned (khoá chat đội theo vùng). Live: PurchaseNetworkMetricsEnabled = 1.
  7. Nội dung động từ CDNClientCodeLive 11/11
    DynamicContentHelper gọi dynamic-content-config.json kèm ETag, lưu DynamicFrameBundle, rồi ghi group avatar / badge / badge_3d / emote / frame / name vào RemoteBundleGroupInfo để tải bundle. Lỗi thì thử lại tối đa 10 lần. Dùng từ level 1.

Vận dụng cho game khác

  • Tách hẳn “luật” (code) khỏi “con số” (config có version + JSON mặc định trong bản cài): game chạy được khi offline lần đầu, và LiveOps đổi thưởng / lịch mà không cần cập nhật app.
  • Mỗi tính năng một cặp AB user mới / user cũ: thử nghiệm onboarding trên người mới mà không làm xáo trộn người cũ, rồi đóng AB bằng cách đưa id vào danh sách đã kết thúc.
  • Có kill switch cho mọi event và cả các cờ an toàn (chống xoá DB hỏng, chống hack giờ): khi có sự cố, server tắt đúng phần lỗi trong vài phút.
  • Nhận định Rủi ro: 67 AB đồng thời cộng hàng chục config có version thì hai người chơi có thể có trải nghiệm rất khác nhau. Cần analytics “vào AB” đầy đủ (game có) và công cụ tra cấu hình theo user để hỗ trợ khách hàng.

Mở khóa & điểm vào

Hạ tầng, luôn chạy. Không có level mở khóa.

Điểm vào:

  • RegisterResponse / RefreshResponse / PingResponse / UpdateUserProgressResponse (AbData, GameSettings, ClientSettings)
  • EnterAbTestRequest/Response (RequestType 24)
  • Get*EventInfoRequest với ConfigVersion
  • CDN dynamic-content-config.json (DynamicContentHelper)

Cách hoạt động

  1. Khi mở app, AbTestData.FillFromLocal nạp nhóm AB từ AbTestTableItem; các manager tạo AbTest (cặp id old/new user) và đọc nhóm = Max(nhóm hai id).
  2. Mỗi response chính mang AbData: AbTestData.UpdateProgress so sánh, phát OnAbTestDataUpdated cho id thay đổi, gửi analytics enter (trừ NoEvtAbIds và EndedAbIds).
  3. Cùng lúc GameSettings mang MaxLevel và Flags: UserManager.ProcessGameSettings xử lý các bit hạ tầng và UserEventHandler chuyển Flags cho từng event manager (AEventManager.DisabledByBackend với get_DisabledBit riêng), Emote (bit 42), Welcome Back (bit 36)… ClientSettings mang RegionChatBanned cho chat đội.
  4. Config sự kiện đi theo mẫu {ConfigVersion, Config}: client gửi version đang có, server chỉ gửi khi đổi; AEventDataHelper lưu JSON vào bảng *TableItem/LocalKeyValue, rỗng thì nạp JSON mặc định trong Resources.
  5. Danh mục cosmetic tải từ CDN bằng ETag và ghi vào RemoteBundleGroupInfo để tải bundle.
  6. Tiến trình dạng số/bitfield lưu ở IntRemoteKeyValue (KeyName 1-21), dạng mảng byte ở ByteArrayRemoteKeyValue (ByteArrayKeyName 1-29), đồng bộ với cờ IsSynced/CanSynced.

Mô tả

  • Client nói chuyện với backend qua hai kênh.
  • Kênh HTTP (FlatBuffers) gom lệnh vào hàng đợi HttpCommands và gửi mỗi 1 giây tới game-service, purchase-service hoặc message-service; mỗi phản hồi là một ResponsePackage có thể kèm RefreshResponse (toàn bộ tiến trình) và RefreshId.
  • Kênh TCP (cổng 6525, social-service) dùng cho chat đội, xin/tặng mạng, Kingdom Pass realtime, event đôi và Kingdom Duels, có echo mỗi giây để phát hiện mất kết nối.
  • Đồng hồ server (ServerTimeHelper) là nguồn thời gian cho mọi timer; client phát hiện chỉnh giờ lùi và "life hack" (hồi mạng bằng cách đổi giờ) rồi ép đồng bộ lại tiến trình.
  • Khi mất mạng hoặc server bảo trì, client hiện NoConnectionDialog / MaintenanceDialog; khi host chính lỗi nhiều lần, client chuyển sang host dự phòng qua Cloudflare.

Thiết kế chi tiết

Giao tiếp server — HTTP gom lô mỗi 1 giây + TCP realtime cho đội / duel, giờ server làm chuẩn, bắt gian lận đổi giờ

Cập nhật 12/11/2026 · đọc code build 34771 + config mặc định trong APK + snapshot thiết bị 11/11/2026. Nhãn:Codeđọc từ pseudo-c / dump.cs của build 34771Nhận địnhsuy luận thiết kế, không phải số liệu đọc được

Tóm tắt thiết kế

Code Hai kênh. HTTP (FlatBuffers): lệnh của mọi manager vào một hàng đợi và được gửi theo lô mỗi 1 giây (timeout 12 giây) tới game-service, purchase-service hoặc message-service. Phản hồi có thể kèm RefreshResponse (toàn bộ tiến độ) khi RefreshId đổi. TCP (social-service, cổng 6525) cho chat đội, xin / tặng mạng, Kingdom Pass realtime, event đôi (Pearls, Hidden Path) và Kingdom Duels; echo mỗi giây, quá 4 lần không trả lời thì kết nối lại.

Code Giờ server là chuẩn cho mọi timer: mỗi phản hồi cập nhật độ lệch server − máy. Client phát hiện giờ máy bị kéo lùi và “life hack” (số mạng hồi nhiều hơn thời gian server thực sự trôi qua): khi đó nó ép tải lại tiến độ từ server và hiện cảnh báo.

Code Lỗi mạng lặp lại (từ lần thứ 4) thì chuyển sang host dự phòng. Trước khi báo mất mạng, client hỏi trạng thái bảo trì để chọn đúng dialog: No Connection / không tải được nội dung / bảo trì. TCP chỉ chạy ở Home, và trong màn chơi khi đang đấu Kingdom Duels.

Luồng người chơi từng bước

  1. Gửi lệnh theo lôClientCode
    BackendHttpService.Send đưa lệnh vào hàng đợi; giờ chưa được server xác thực thì gửi Ping thay. ManualUpdate xả mỗi 1 giây; Register / SocialConnect dùng SendImmediately. User tạm thì giữ lệnh và đăng ký trước. Mỗi request mang header phiên bản, user id, nền tảng, ngôn ngữ.
  2. Ping khi mở / quay lạiClientCode
    OnAppStart / OnAppResume → Ping, các manager gắn thêm lệnh của mình (AppendCommandsToPing: event info, FeatureDependency, hộp thư…). Không ping khi đang mua, app pause, user tạm, đang đăng nhập, hoặc vừa quay lại sau quảng cáo.
  3. Host dự phòng và bảo trìClientCode
    SwitchNetworkScheme: lỗi lần thứ 4 thì đổi sang host fallback (chế độ “cloudflare”). Không vào được game-service thì hỏi 2 endpoint bảo trì; đang bảo trì thì hiện “The system is under maintenance. Please check back soon.”
  4. Mất mạngGiao diệnCode
    NoConnectionDialog “No Connection! Please check your internet connection” hoặc NoConnectionForContentDialog khi thiếu nội dung tải về. Phần lớn gameplay vẫn chạy offline; dữ liệu chờ đồng bộ (xem SaveSync).
  5. TCP: kết nối và echoClientCode
    Vào Home thì thử kết nối 10 lần (chờ 0,5 s rồi 1 s), sau đó xác thực (tối đa 10 lần), lấy chat đội. Echo mỗi 1 giây; > 4 echo không trả lời thì “Connection lost” và kết nối lại. Pause lâu (20 s) thì ngắt. Gói tối đa 1 MB, tiền tố 4 byte độ dài.
  6. Tin đẩy realtimeServerCode
    Đổi mạng, có người xin vào đội, đăng nhập từ máy khác, dữ liệu Kingdom Pass, event đôi Pearls / Hidden Path, thẻ được tặng, Kingdom Duels (tìm được đối thủ, điểm), reaction chat; ForceLogResponse bắt client gửi log lên.
  7. Chống đổi giờ / life hackClientCode
    Lúc pause lưu giờ máy, giờ server và số mạng. Quay lại: giờ máy lùi thì reset trạng thái vô hạn offline. IsThereLifeHack so số mạng đã hồi với thời gian server thật (dung sai 60 s); phát hiện thì “Force refresh progress”, hiện TimeHackDialog, gửi LifeHack. Huỷ nếu level không tăng.

Vận dụng cho game khác

  • Gom lệnh của mọi tính năng vào một hàng đợi gửi mỗi giây và cho Ping “chở” thêm lệnh của các manager: ít request, ít pin, một chỗ để xử lý lỗi và thử lại.
  • Lấy giờ server làm chuẩn cho mọi timer và kiểm tra “mạng hồi có khớp thời gian thật không” để chặn gian lận đổi giờ mà không chặn người chơi offline bình thường.
  • Nhận định Chỉ dùng TCP cho phần thật sự cần realtime (chat, duel, tặng mạng) và chỉ ở Home: tiết kiệm kết nối, đổi lại các event đội cập nhật chậm hơn khi người chơi đang trong màn.

Mở khóa & điểm vào

Luôn bật. Một số phần bị backend điều khiển bằng cờ: HttpDisabled, CloudflareEnabled, các cờ *NetworkMetricsEnabled (App.LocalKeyValue), LifeHackControlDisabledByBackend.

Điểm vào:

  • Mọi thao tác gửi dữ liệu (thắng level, mua, nhận thưởng…)
  • Ping khi mở app / quay lại app (ServerTimeHelper.OnAppStart/OnAppResume)
  • Kết nối TCP khi vào Home (UserBackendTcpManager.StartTryConnectLoop)
  • NoConnectionDialog, NoConnectionForContentDialog, MaintenanceDialog, TimeHackDialog

Cách hoạt động

  1. URL backend không có sẵn dạng đầy đủ: HttpCommandsHandlers..ctor gọi PrepareBackendUris(Uri.UriSchemeHttps), hàm này ghép scheme + "://" + host với host là const BackendGameUrl = game-service.prod.rylkngdm.com/api và BackendPurchaseUrl = purchase-service.prod.rylkngdm.com/api.
  2. Mảng NetworkSchemes = ["https", "cloudflare"]; mỗi lần lỗi SwitchNetworkScheme tăng bộ đếm, từ lần thứ 4 (counter ≥ 3) đổi scheme; nếu scheme là "cloudflare" (ShouldUseCloudflare) thì dùng host dự phòng game-service.fallback-prod.rylkngdm.com/api / purchase-service.fallback-prod… (vẫn https).
  3. Message-service (message-service.prod… / fallback-prod…) và TCP social-service.prod.rylkngdm.com:6525 là static.
  4. Mỗi request mang header chung (RequestHeaderHelper.AddCommonHeaders: x-rk-version/x-version = 'v{build}', x-rk-userid/x-userid, x-rk-platform/x-platform = android|ios, x-lg = ngôn ngữ).
  5. BackendHttpService.Send đưa lệnh vào hàng đợi; nếu giờ chưa được server xác thực thì gửi Ping thay thế.
  6. ManualUpdate xả hàng đợi mỗi CommandSendPeriod = 1 giây, timeout lệnh 12.000 ms.
  7. TryValidateUser chặn lệnh khi user chưa đăng ký (gọi RegisterIfNeeded).
  8. Ping bị bỏ khi đang mua, app đang pause, user tạm hoặc đang đăng nhập.
  9. Trước khi báo lỗi mạng, client hỏi trạng thái bảo trì ở https://maintenance.prod.rylkngdm.com/status và Cloud Function backendMaintenanceMode (header x-rk-api-version: 2).
  10. Kênh TCP: BackendTcpService thử kết nối 10 lần (chờ 0,5 s / 1 s), sau đó UserBackendTcpManager gửi AuthenticateRequest (tối đa 10 lần).
  11. Echo mỗi 1 giây; quá 4 echo không trả lời → 'Connection lost' → DisconnectAndRetry.
  12. TCP chỉ được phép ở Home, và ở Game khi đang trong trận Kingdom Duels.
  13. Thời gian: mọi phản hồi cập nhật ST (giờ server) và STD (lệch server-client); ServerTimeUtcInMs = giờ máy + lệch.

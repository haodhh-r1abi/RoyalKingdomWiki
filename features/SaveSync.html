Mô tả

  • Toàn bộ dữ liệu người chơi nằm trong hai file SQLite ở app_pFiles: App (dữ liệu thiết bị: user id, token, giờ server, cấu hình tải từ server, cache CRC bundle) và U_<userId> (tiến trình của từng user: level, coin, kingdom, inventory, mỗi event một bảng).
  • Mỗi dòng key-value có cờ đồng bộ: dòng Synced = 0, SyncBlocked = 0 là thay đổi chờ gửi, SyncBlocked = 1 là dữ liệu chỉ lưu máy.
  • Client gửi tiến trình qua UpdateUserProgressRequest theo 4 nhóm (BasicData, GameData, KingdomData, ArenaData) và các khóa số IntRemoteKeyValue / chuỗi ByteArrayRemoteKeyValue qua SetKeyValueRequest.
  • Khi server có bản mới hơn (RefreshId khác) nó gửi RefreshResponse; client chỉ nhận nếu level server không thấp hơn level máy, ngược lại từ chối và đẩy dữ liệu máy lên.
  • DB được commit khoảng mỗi giây, khi pause/quit, và tự xoá nếu hỏng.

Tóm tắt thiết kế

CodeLive 11/11 Dữ liệu nằm trong 2 file SQLite: App (thiết bị: giờ server, config tải về, cache CRC bundle) và U_<userId> (tiến độ: level, coin, kingdom, inventory, mỗi event một bảng; snapshot có 41 bảng). Mọi ghi nằm trong transaction mở sẵn và được commit khoảng mỗi giây, cộng thêm khi pause / thoát.

Code Mỗi dòng key-value có cờ Synced / SyncBlocked: 1/0 là đã đồng bộ, 0/0 là chờ gửi, 0/1 là chỉ lưu trên máy. Tiến độ gửi qua UpdateUserProgress theo 4 nhóm (BasicData, GameData, KingdomData, ArenaData), chỉ nhóm có thay đổi. Tiến độ event dạng số / chuỗi đi qua SetKeyValue (21 khoá số + 29 khoá chuỗi).

Code Khi server có bản mới (RefreshId khác), client chỉ nhận nếu level server không thấp hơn level máy; ngược lại nó từ chối và đẩy dữ liệu máy lên. Arena có luật riêng theo cup. DB hỏng thì tự xoá (tối đa 1 lần mỗi phiên) và tải lại từ server.

Luồng người chơi từng bước

  1. Mở DBClientCode
    AppDatabaseService tạo bảng thiết bị (LocalKeyValue, PlayerData, Purchase, TeamData, CRCTable, KingdomInteractionTime). UserDatabaseService(userId) tạo bảng tiến độ (LocalKeyValue, IntRemoteKeyValue, ByteArrayRemoteKeyValue, LifeInbox, AbTestTableItem và khoảng 30 bảng *TableItem cho event). Đổi user thì đổi / tạo file mới.
  2. Ghi và commitClientCode
    Ghi đánh dấu “bẩn” (RaiseShouldSaveFlag). ManualUpdate commit khi frameCount chia hết cho (offset + TargetFrameRate), tức khoảng 1 giây; user DB lệch 1 frame. OnApplicationPause / Quit luôn commit.
  3. Gửi tiến độClientCode
    SendDataToBackend (thắng / thua màn, mua, thoát…) gom lệnh của các manager; UpdateUserProgressHttpCommand.Build chỉ đóng gói nhóm có khoá chờ gửi. Server OK thì DataSyncedWithBackend đặt Synced = 1. Không gửi khi đang ở giữa “thắng” và “nổ lượt dư”.
  4. Đồng bộ khoá eventClientCodeLive 11/11
    IntRemoteKeyValue (KeyName 1–21: tutorial, gameplay, Blitz, Team Clash, Pearls…) và ByteArrayRemoteKeyValue (29 khoá: Cube Blast, Magic Carnival, Weekly Goals, Medal Missions…, giá trị nối bằng “§”). Dòng IsSynced = 0 và CanSynced = 1 được gửi qua SetKeyValue. Live: 17 khoá số và 28 khoá chuỗi, tất cả đã đồng bộ.
  5. Refresh từ serverServerCode
    RefreshProgress: RefreshId bằng nhau (và không ép) thì bỏ qua. Level server ≥ level máy thì ghi đè dữ liệu máy (gửi analytics RefreshProgress). Level server < level máy thì “Reject Refresh”, cập nhật RefreshId và đẩy dữ liệu máy lên. Trong lúc refresh, Ping bị chặn.
  6. DB hỏng / hỗ trợClientCodeLive 11/11
    Pause / Quit mà SQLite báo hỏng: có mạng, đang ở Home, chưa bị server tắt (CorruptDbWipeDisabled) thì xoá dữ liệu và thoát, lần mở sau tải lại. Ticket hỗ trợ có thể kèm bản sao DB (tối đa 2 MB) khi DBDumpSupportLogEnabled = 1 (live = 1).

Vận dụng cho game khác

  • Tách rõ “dữ liệu thiết bị” và “dữ liệu người chơi” thành 2 file: đổi tài khoản trên cùng máy chỉ là đổi file, không lẫn dữ liệu.
  • Gắn cờ đồng bộ lên từng dòng và gửi theo nhóm thay đổi: chơi offline thoải mái, lên mạng chỉ gửi phần đã đổi.
  • Nhận định Rủi ro: luật “level cao hơn thắng” đơn giản nhưng có thể làm mất tài nguyên tiêu hao (coin, booster) khi hai máy cùng chơi một tài khoản ở cùng level. Với game nhiều tài nguyên mềm nên cân nhắc so thêm thời điểm hoặc tổng chi tiêu.

Bảng tổng hợp mọi tính năng đã làm chi tiết: RoyalKingdom_ThietKeChiTiet.xlsx.

Mở khóa & điểm vào

Luôn bật. Cờ backend CorruptDbWipeDisabled (PlayerPrefs) tắt tự xoá DB hỏng; DBDumpSupportLogEnabled = 1 (live 11/11) cho phép gửi file DB kèm ticket hỗ trợ.

Điểm vào:

  • Mọi thay đổi dữ liệu trong game (ghi UserKeyValue / bảng event)
  • Pause / quit app (commit)
  • Ping / UpdateUserProgress (gửi), RefreshResponse (nhận)
  • Đổi user (MoveDbFile / CreateNewUserDb)

Cách hoạt động

  1. AppDatabaseService mở App, UserDatabaseService(userId) mở U_<userId> (DbFileHelper.GetAppDbPath/GetUserDbPath) và tạo bảng bằng create table if not exists.
  2. Mọi ghi đi qua SqLiteDbWrapper trong một transaction mở sẵn; RaiseShouldSaveFlag đánh dấu bẩn và DatabaseService.ManualUpdate commit khi frameCount chia hết cho SaveIntervalOffset + TargetFrameRate (≈ 1 giây; user DB offset = 1), rồi mở transaction mới.
  3. OnApplicationPause/Quit luôn commit.
  4. Bảng LocalKeyValue(Key, Value, Synced, SyncBlocked): SetString(key, value, synced) ghi Synced = synced, SyncBlocked = !synced; nên khóa chỉ-máy có 0/1, khóa đã đồng bộ có 1/0 (đúng như snapshot: KingdomProgress, TaskClaimProgress, PictureId là 1/0, còn lại 0/1).
  5. Câu SQL LocalKeyValueTable.Query đếm các khóa chưa đồng bộ theo 4 nhóm: BasicData (PictureId, GenericData), GameData (Level, FullLivesTime, UnlimitedLivesEndTime, Coins, Potions, InGameInventory, PreLevelInventory, Unlimited*EndTime, LastDestroyedTime, LastFixedTime, LastShieldEarnTime, LifeInbox, ShieldCount, CumulativeExperience), KingdomData (KingdomProgress, TaskCompletionProgress, TaskClaimProgress), ArenaData (ArenaUserConfigVersion, ArenaUserGroupId, ArenaUserCups, ArenaRound, ArenaUserLastSeenCups).
  6. UpdateUserProgressHttpCommand.Build chỉ tạo offset cho nhóm có thay đổi; khi server trả OK, UserManager.DataSyncedWithBackend chạy UPDATE LocalKeyValue SET Synced = 1 WHERE Key IN (…) and SyncBlocked = 0.
  7. Song song, IntRemoteKeyValue(Key int, Value bigint, IsSynced, CanSynced) giữ tiến độ dạng số theo enum KeyName và ByteArrayRemoteKeyValue giữ chuỗi theo ByteArrayKeyName; GetSyncRequiredKeyValues lấy dòng IsSynced = 0 để gửi SetKeyValueRequest, server gửi lại qua KeyValueData (UpdateProgress, InsertValueIfKeyNotExist).
  8. Xung đột: UserManager.RefreshProgress bỏ qua nếu RefreshId client = server (và không force); nếu level server < level client thì từ chối ('Reject Refresh Level Client/Server'), cập nhật RefreshId và SendDataToBackendAfterRejectedRefresh; ngược lại UserContext.RefreshProgress ghi đè dữ liệu máy.
